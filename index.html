What the migration actually takes

The client is confidential, so names and addresses are left out. The work isn’t.

One pipeline for every service

Each of the 50+ services goes through the same path: a cloud branch, a Jenkins build that requires a version tag and an approval, the registry, then ArgoCD. I wrote small scripts that read a repo, translate its on-premise settings to cloud ones and generate the manifests, so bringing a new service across takes minutes.

Syncing data over a link that drops packets

The connection between the data center and the cloud loses 30–47% of its packets. I wrote a Python service that reads MariaDB binlogs, replays them into RDS without creating duplicates and saves its position as it goes. It runs three source databases in parallel and survives restarts.

Checking the gateway against what’s really running

The API gateway has 700+ routes. Comparing every backend in its config with the services actually deployed turned up about 30 that were missing, before users ran into them.

Catching the quiet failures

A database that had been down for five days because its log filled the disk. A worker that crash-looped inside a container Kubernetes still reported as healthy. Each fix shipped together with the alarm or restart policy that would have caught it sooner.
