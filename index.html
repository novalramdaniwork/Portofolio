What the migration actually takes

The client is confidential, so names and addresses are left out. The work isn’t.

50+services

One pipeline for every service

Each service goes through the same path: a cloud branch, a Jenkins build that needs a version tag and an approval, the registry, then ArgoCD. Small scripts read each repo, translate its on-premise settings and generate the manifests, so bringing a service across takes minutes.

30–47%packet loss

Syncing data over a link that drops packets

I wrote a Python service that reads MariaDB binlogs, replays them into RDS without creating duplicates and saves its position as it goes. Three source databases run in parallel and it survives restarts.

700+gateway routes

Checking the gateway against what’s running

Comparing every backend in the gateway config with the services actually deployed turned up about 30 that were missing, before users ran into them.

5 daysunnoticed, once

Catching the quiet failures

A database down for five days because its log filled the disk. A worker crash-looping inside a container Kubernetes called healthy. Every fix shipped with the alarm or restart policy that would have caught it sooner.
