REPORT-01

Fault Log — Current Infrastructure & Pain Points

CONTEXT: this migration was designed for the production infrastructure I inherited and operate as sole DevOps. The existing setup works but has scaling and operational limitations. Infrastructure details are intentionally generalized for confidentiality.
Fixed on-premise capacity

Physical servers with fixed capacity. Scaling up requires hardware procurement — slow, expensive, and misaligned with dynamic workload demands.

Manual database operations

Standalone MariaDB, MongoDB, Redis, RabbitMQ, and MinIO servers need manual maintenance, patching, and failover. No automated backup or point-in-time recovery.

Single point of operational dependency

As the only DevOps engineer, managing multiple standalone services across dev/staging/prod is operationally heavy. Managed services would drastically cut this overhead.

No disaster recovery strategy

No geographic redundancy — a datacenter issue would take down all environments with no automatic failover path.

CURRENT STACK: Nginx Proxy Manager (entry) · ModSecurity + CrowdSec (WAF/IPS) · KrakenD ×3 · RKE2 + Rancher (dev/staging/prod) · MariaDB ×3 (2 master + 1 replica) · MongoDB · Redis · RabbitMQ · MinIO — all standalone.

Schematic — Target Architecture

All stateful services move to Huawei managed offerings — databases to RDS, messaging to DMS, cache to DCS, storage to OBS. Compute runs in CCE with separate node pools per region. A WireGuard tunnel maintains on-premise connectivity during the parallel running phase.

REPORT-03

Procedure — Migration Strategy

Designed as a phased parallel-running approach: cloud is built alongside on-premise, both run simultaneously until cloud is fully validated, and only then does DNS cut over. As sole DevOps, this guarantees a working rollback path without needing a second person to manage the transition.

01
Cloud setupEST. 2–3 WEEKS
  • Provision VPC, subnets, network policies
  • Deploy CCE cluster — KR and INA node pools
  • Configure RDS (MariaDB KR, INA, Temporal), DCS (Redis), DMS (RabbitMQ), DDS (MongoDB), OBS
  • Set up SWR container registry — point CI/CD (Jenkins) here
  • Establish WireGuard VPN tunnel to on-premise
  • Configure WAF, HSS, LTS, CES, SMN observability stack
02
Parallel runningEST. 3–4 WEEKS
  • Deploy microservices to CCE — replicate on-prem configuration
  • Deploy KrakenD API Gateway to KR and INA namespaces
  • Sync on-prem databases to cloud RDS (initial data migration)
  • Run parallel traffic via internal DNS — validate responses
  • Load test cloud against on-prem benchmarks
  • Write and validate rollback runbooks
03
Cutover & decommissionEST. 1–2 WEEKS
  • Lower DNS TTL 48 hours before the cutover window
  • Execute cutover during the lowest-traffic window
  • Intensive monitoring for 72 hours post-cutover
  • Keep on-premise warm as rollback for 1–2 weeks
  • Decommission on-premise and tear down VPN once cloud is confirmed stable

REPORT-06

Parts List — Key Design Decisions

Phased migration

As sole DevOps, a big-bang migration is too risky. Running cloud in parallel until stable means there's always a working fallback — critical when one person is responsible for the entire infrastructure.

// RISK STRATEGY
KrakenD stays in CCE

Rather than swapping in a cloud-native API gateway, the same KrakenD config is deployed inside CCE — smaller migration scope, preserved routing logic, less risk, faster migration.

// API GATEWAY
All DBs → managed

MariaDB, MongoDB, Redis, RabbitMQ all move to managed services — eliminating the biggest solo-DevOps burden: standalone servers, manual backups, manual failover. The time saved goes back into delivery.

// DATABASE
MinIO → OBS

Self-managed MinIO needs disk management and backup orchestration. OBS is S3-compatible, so most MinIO clients work without code changes. Major operational simplification, minimal app impact.

// OBJECT STORAGE
WAF + HSS replace ModSec

ModSecurity and CrowdSec require active rule management on self-managed Nginx. Huawei WAF and HSS deliver managed threat detection — freeing the solo DevOps from security-rule maintenance.

// SECURITY
WireGuard as migration bridge

A simple, high-performance encrypted tunnel for the parallel phase. Easier to configure than IPSec, lower latency for DB replication, and trivially torn down post-migration.
