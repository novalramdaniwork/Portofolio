01

Current Infrastructure & Pain Points

Context: This migration was designed for the current production infrastructure I inherited and operate as sole DevOps. The existing setup works but has scaling and operational limitations that cloud migration would resolve. Infrastructure details are intentionally generalized for confidentiality.

Fixed On-Premise Capacity
Current infrastructure runs on physical servers with fixed capacity. Scaling up requires hardware procurement — slow, expensive, and doesn't align with dynamic workload demands.
Manual Database Operations
Standalone MariaDB, MongoDB, Redis, RabbitMQ, and MinIO servers require manual maintenance, patching, and failover handling. No automated backup or point-in-time recovery.
Single Point of Operational Dependency
As the only DevOps engineer, managing multiple standalone services across dev/staging/prod clusters is operationally heavy. Managed cloud services would drastically reduce this overhead.
No Disaster Recovery Strategy
On-premise infrastructure has no geographic redundancy. A datacenter issue would take down all environments with no automatic failover path.

02

Target Architecture

The target architecture moves all stateful services to Huawei Cloud managed offerings — databases to RDS, messaging to DMS, cache to DCS, storage to OBS. Compute runs in CCE with separate node pools per region (KR and INA). A WireGuard VPN tunnel maintains on-premise connectivity during the parallel running phase.

Target Architecture · Huawei Cloud — Designed by Noval Ramdani
03

Migration Strategy

Designed as a phased parallel-running approach. Cloud infrastructure is built alongside on-premise — both run simultaneously until cloud is fully validated. Only then does DNS cutover happen. As the sole DevOps engineer, this approach ensures there's always a working rollback path without requiring a second person to manage the transition.

Est. 2–3 weeks

02
Parallel Running
Est. 3–4 weeks
Deploy all workloads to CCE with KrakenD API Gateway per namespace. On-premise continues serving production. Validate cloud environment — data consistency, performance, and failover.
Deploy microservices to CCE — replicate on-prem configuration
Deploy KrakenD API Gateway to KR and INA namespaces
Sync on-prem databases to cloud RDS (initial data migration)
Run parallel traffic via internal DNS — validate responses
Load test cloud environment against on-prem benchmarks
Write and validate rollback runbooks
03
Cutover & Decom
Est. 1–2 weeks
DNS cutover to cloud. On-premise stays on standby as rollback for 1–2 weeks. Once cloud stability is confirmed, decommission on-premise and remove VPN tunnel.
Lower DNS TTL 48 hours before cutover window
Execute cutover during lowest-traffic window
Intensive monitoring for 72 hours post-cutover
Keep on-premise warm as rollback for 1–2 weeks
Decommission on-premise and VPN once cloud confirmed stable

06

Key Design Decisions

Phased Migration
As the sole DevOps, a big-bang migration is too risky. Running cloud in parallel until stable means there's always a working fallback — critical when you're the only person responsible for the entire infrastructure.
// Risk Strategy
KrakenD Stays in CCE
Rather than replacing KrakenD with a cloud-native API gateway, the same KrakenD config is deployed inside CCE. This keeps the migration scope smaller and preserves existing API routing logic — less risk, faster migration.
// API Gateway
All DBs → Managed
MariaDB, MongoDB, Redis, RabbitMQ — all move to Huawei managed services. Eliminates the biggest solo DevOps burden: maintaining standalone servers, manual backups, and failover. The time saved goes back into application delivery.
// Database
MinIO → OBS
Self-managed MinIO requires disk management and backup orchestration. Huawei OBS is S3-compatible — most MinIO clients work without code changes. Significant operational simplification with minimal application impact.
// Object Storage
WAF + HSS Replace ModSec
ModSecurity and CrowdSec require active rule management on self-managed Nginx. Huawei WAF and HSS provide managed threat detection with less operational overhead — freeing the solo DevOps from security rule maintenance.
// Security
WireGuard for Migration Bridge
WireGuard provides a simple, high-performance encrypted tunnel between on-premise and cloud during the parallel phase. Simpler to configure than IPSec, lower latency for database replication, and easy to tear down post-migration.
// Connectivity
